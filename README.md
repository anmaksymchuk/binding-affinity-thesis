# Binding affinity prediction: GNN + quantum descriptors

Код baseline-модели для диссертации: предсказание аффинности связывания белок–лиганд (PDBbind) с помощью графовой нейросети (gated GATv2) и опциональной вариационной квантовой головы (VQC, PennyLane).

## Файлы

| Файл | Назначение |
|---|---|
| `config.py` | Пути и гиперпараметры |
| `dataset.py` | Построение графов комплексов (лиганд + карман) |
| `Graph_Attention_Layer.py` | Слой графового внимания |
| `model.py` | Модель: GNN-энкодер, MLP / VQC голова, ESM через FiLM |
| `trainer.py` | Цикл обучения и валидации |
| `utils.py` | Метрики и вспомогательные функции |
| `main.py` | Точка входа: обучение и тест |
| `cleansplit.py` | Таблица комплексов CleanSplit ∩ R1, фильтры меток, сплит по ID |
| `esm_converter.py` | Предрасчёт эмбеддингов белков ESM-2 → `esm_embeddings.pt` |

## Данные и протокол

Протокол: **PDBbind v2020.R1 + CleanSplit** (Graber et al., 2025). Train = CleanSplit train ∩ R1, валидация = случайные 15 % train (`val_mode = "random"`; можно переключить на фолды GEMS: `val_mode = "gems_fold"`, `fold = 0..4`), тест = CASF-2016 (основной), а также CASF-2016 indep, CASF-2013 и CASF-2013 indep. Метки берутся из индекса R1, pK = −log10(Kd/Ki/IC50).

Данные в репозиторий **не входят** (лицензия PDBbind и размер). Что нужно положить в рабочую папку:

- `PDBbind_v2020R1/` — распакованный пакет «Protein-ligand complex structures» из PDBbind v2020.R1 (PDBbind+, нужна регистрация). Вложенность папок не важна: файлы `<id>_ligand.mol2|sdf` и `<id>_pocket.pdb` ищутся рекурсивно;
- индексный файл с аффинностями из той же загрузки. Путь задаётся в `config.r1_index_file`; если его там нет, скрипт ищет `INDEX_general_PL*` внутри `PDBbind_v2020R1/`;
- `esm_embeddings.pt` (нужен только для `full` и `esm_only`), создаётся скриптом `esm_converter.py`.

Списки CleanSplit уже лежат в `splits/cleansplit/` (см. README там).

`data/`, `processed/` и `outputs/` создаются автоматически и игнорируются git.

## Запуск

```bash
pip install -r requirements.txt
python cleansplit.py      # таблица data/complexes.csv + отчёт о покрытии
python esm_converter.py   # один раз, если нужен ESM
python main.py
```

### Ligand-only baseline (проверка шортката)

`graph_input = "ligand"` в `config.py` оставляет в графе только атомы лиганда и его ковалентные связи: атомы кармана, вода и все межмолекулярные рёбра выбрасываются при загрузке графа. Кэш графов комплексов используется как есть, пересобирать его не нужно. Модель, обучение, фолды и выбор чекпойнта те же, меняется только вход, поэтому разница с полной моделью говорит о вкладе белка и геометрии. Папка результатов получает суффикс `_ligandonly`, так что полный запуск с тем же `experiment_name` не перезаписывается.

Перед первым запуском ligand-only стоит проверить графы на реальных данных: `python tools/check_ligand_only.py [--n 500]` прогоняет выборку комплексов через `DataLoader` (тот же путь, что при обучении) и проверяет, что в графе остались только лигандные вершины, что список рёбер совпадает с ковалентными связями лиганда пара в пару, что обе ветви одинаковы, что не осталось контактных рёбер и весов-расстояний, что признаки атомов и метка не изменились. При ошибке скрипт падает с ненулевым кодом.

**Важно:** кэш графов и сплит скрипт берёт из `config.py`, поэтому сначала выставьте настройки пилота (`pocket_hydrogens`, `graph_input`, `val_mode`, `fold`), а потом запускайте проверку, иначе она прочитает другой кэш. С `--compare_split <папка запуска>` она ещё и пересчитывает сплит и проверяет, что train, val и все тестовые наборы состоят из тех же комплексов, что у готового запуска полной модели: без этого парное сравнение по комплексам некорректно.

Независимый контроль без нейросети: `python tools/ligand_fp_baseline.py <папка запуска>` считает Morgan fingerprints лиганда и обучает градиентный бустинг на тех же train/val/test ID (берёт их из `split_info.json` этого запуска); число деревьев выбирается по val, как эпоха у GNN. По умолчанию `--loss squared_error` (та же величина, что в отчётной RMSE), есть `absolute_error`. Лиганды, которые не удалось разобрать, выписываются в `missing_ids.csv`: парное сравнение с GNN делается по пересечению `pdb_id`. Результаты в `<папка запуска>/ligand_fp/`. Нужен `scikit-learn` (есть в Colab).

Ligand-only использует ту же архитектуру, что полная модель (matched capacity): обе ветви получают один и тот же граф лиганда, потому что контактные рёбра удалены. Это не отдельный однобраншевый лигандный энкодер, и в тексте работы это нужно называть именно matched-architecture baseline.

`cleansplit.py` нужно перезапускать, если поменялись структуры или индексный файл. Фильтры меток (`drop_censored_labels`, `keep_approx_labels`) `main.py` применяет сам, поэтому после их изменения ничего пересобирать не нужно: графы строятся для всех комплексов с меткой. Если метки в `complexes.csv` изменились, `main.py` заметит расхождение с кэшем графов и попросит удалить `processed/graphs_<tag>*`.

## Что сохраняется в `outputs/<model>_<val15|fold k>_seed<s>/`

| Файл | Содержимое |
|---|---|
| `split_info.json` | Настройки сплита, sha256 файлов сплита и `complexes.csv`, списки train/val/test ID, исключённые ID с причиной (`no_structure`, `no_label`, `censored_label`, `approx_label`, `graph_failed:<причина>`) |
| `test_metrics.pt` | Метрики по каждому тестовому набору |
| `test_predictions.csv` | Предсказания по комплексам: `test_set, pdb_id, y_true, y_pred` |
| `val_predictions.csv` | То же для валидации (лучшая модель) |
| `similarity/` | Результаты `tools/similarity_analysis.py` |
| `best_model_rmse.pt`, `model_final_pKd.pt`, `y_stats.pt`, `training_history.pt` | Как раньше |
| `last_checkpoint.pt` | Полное состояние обучения после последней эпохи (модель, оптимизатор, scheduler, история). Нужен для продолжения после обрыва |

### Если Colab отключился во время обучения

Просто запустите `python main.py` ещё раз с теми же настройками: он найдёт `last_checkpoint.pt` и продолжит со следующей эпохи (`resume = True` в `config.py`). Если сплит или настройки обучения поменялись, он откажется продолжать. Если в папке результатов уже лежит `best_model_rmse.pt` без `last_checkpoint.pt` (запуск старой версии кода), `main.py` не станет его перезаписывать: переименуйте папку. Протестировать сохранённую модель без обучения можно через `python tools/evaluate.py`.

Графы сохраняются частями по 1000 комплексов: `processed/graphs_<tag>_shardNNN.pt` и `.json` (в `.json` лежат ID части и причины, по которым графы не построились). Если построение прервалось, готовые части при следующем запуске используются повторно.

## Анализ по сходству с train

`tools/similarity_analysis.py` использует матрицы попарного сходства GEMS (Zenodo, https://doi.org/10.5281/zenodo.17190227: `pairwise_similarity_matrices.tar.gz` и `pairwise_similarity_complexes.json`): Tanimoto лигандов, TM-score белков и RMSD лиганда после выравнивания карманов. Для val, каждого набора CASF и случайной выборки train (без самого себя) он считает сходство с ближайшим комплексом train, число комплексов train, проходящих критерий фильтра CleanSplit, и прогноз поискового baseline GEMS (взвешенное среднее pK пяти самых похожих комплексов нашего train). Если в папке запуска есть `val_predictions.csv` и `test_predictions.csv`, к этому добавляются ошибки модели в зависимости от сходства.

```bash
python tools/similarity_analysis.py --sim_dir <папка с матрицами> --run_dir outputs/gnn_only_val15_seed42
```

Матрицы читаются через memory map, поэтому в память загружаются только нужные строки.

Подробные таблицы и графики по `similarity_per_complex.csv` (ошибка по сходству лиганда, по разнице pK с ближайшим соседом, сжатие прогнозов к среднему, сравнение с поиском) строит `python tools/similarity_report.py --run_dir <папка запуска>`; результаты в `<папка запуска>/similarity/report/`.

Контрольные проверки гипотезы о соседях с другой аффинностью (обогащение без прогнозов модели, перевзвешивание val по смеси dpK, dpK внутри диапазонов pK, парное сравнение с поиском с бутстрепом, смещение против константы, тип ближайшего соседа, рекалибровка) считает `python tools/similarity_checks.py --run_dir <папка запуска>`; таблицы в `<папка запуска>/similarity/checks/`.

Ранжирование внутри мишени на CASF (ranking power: Spearman/Kendall по мишеням, ошибка разности pK внутри мишени, разложение ошибки на сдвиг мишени и остаток, кластерный бутстреп) считает `python tools/casf_ranking.py --sim_dir <папка с матрицами GEMS> --run_dir <папка запуска>`; мишени восстанавливаются по матрице TM-score (или берутся из официальных `CoreSet.dat` через `--coreset` для CASF-2016 и `--coreset2013` для CASF-2013; без них разбиение приблизительное и сравнивать с опубликованными бенчмарками CASF нельзя), результаты в `<папка запуска>/similarity/ranking/`. Фигуру по мишеням в стиле GEMS Extended Data Fig. 1 (|ошибка|, Pearson и Spearman внутри каждой мишени, модель против поиска) рисует `python tools/plot_per_target.py --run_dir <папка запуска>` после `casf_ranking.py`.

Сводку по 5 фолдам GEMS (то, что идёт в таблицу диплома) собирает `python tools/summarize_folds.py --prefix gnn_only_noH_amp`: метрики по каждому фолду, mean ± std по фолдам (как в GEMS Fig. 3 — среднее одиночных моделей), отдельно ансамбль пяти моделей (среднее предсказаний — это другая модель, в среднее не смешивается), out-of-fold метрики по объединённым валидационным частям и таблица сравнения с опубликованными числами на CASF-2016. Скрипт проверяет, что валидационные части не пересекаются, что фолды совпадают с `split_info.json` и что метка одного комплекса одинакова во всех фолдах. Результаты в `outputs/cv_summary_<prefix>/`.

Ранжирование внутри мишени по всем фолдам считает `python tools/ranking_folds.py --coreset <CoreSet2016.dat> --coreset2013 <CoreSet2013.dat> --prefix gnn_only_noH_amp`: Spearman и Kendall внутри мишени, low/high-level success, RMSE и наклон парных разностей pK — mean ± std по фолдам и отдельно для ансамбля. Нужны только `test_predictions.csv` каждого фолда и официальные `CoreSet.dat`, матрицы сходства не нужны, поэтому это дёшево для пяти фолдов. Полный разбор с поисковым baseline, бинами по Tanimoto и разложениями остаётся в `tools/casf_ranking.py`. Результаты в `outputs/cv_summary_<prefix>/ranking/`.

Два прогона с одним и тем же разбиением сравнивает по комплексам `python tools/compare_runs.py --run_a <папка A> --run_b <папка B> --labels A B`: парный бутстреп разницы RMSE и разница ошибок по квартилям размера кармана, числа водородов кармана, размера лиганда, pK и сходства с train; результаты в `<папка B>/compare_vs_A/`.
